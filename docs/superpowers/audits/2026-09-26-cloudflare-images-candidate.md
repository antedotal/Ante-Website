# Cloudflare Images candidate after the HEIC CPU failure

The paired backend's `2026-09-26-photo-normalizer-hosted-probe.md` rejects the current magick-wasm configuration for full proof uploads. This note identifies another candidate; it is not runtime selection or a deployment.

Current Cloudflare documentation says the Images binding accepts raw byte streams, including a request body, without a public source URL. It can resize and encode output; responses are not automatically cached. Keep Ante responses private/no-store and do not follow the documentation's optional public-cache examples. `.info()` reports format, dimensions and file size, but the inspected page does not establish comprehensive still-image, transparency, auxiliary-HEIC or corruption validation. `anim:false` converts animation to a still; it does not implement the user's requirement to reject animations. [Binding documentation](https://developers.cloudflare.com/images/optimization/binding/)

The documented binding input cap is20MB, above Ante's existing10MiB proof envelope. HEIC is listed among input formats and JPEG/PNG among outputs. Those listings do not prove every HEIF/container variant or the exact failing synthetic HEIC works. Verify orientation-aware geometry, no upscale/crop, metadata stripping, transparency, still-image rejection, bounded outputs and actual resource behavior. [Limits and formats](https://developers.cloudflare.com/images/get-started/limits/)

Images Free includes5,000 unique transformations per month. New transformations above that allowance fail, with no overage charge on Free. Direct binding calls use this metric; `.info()` calls are not billed. This is distinct from paid hosted-image storage, which Ante does not need for this candidate: final normalized storage can remain private in Supabase. Account-specific availability and actual configuration still require verification. No subscription or billing change has been made. [Pricing](https://developers.cloudflare.com/images/pricing/)

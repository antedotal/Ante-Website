# Photo processing scope: local source acceptance

26 September 2026. This patch adds one synchronous fail-fast processing slot per loaded server module/isolate. The server-only raw validator checks cheap MIME/body/signal/content-length failures before admission, then keeps the slot through body read, PNG preflight and full decode. PUT enters after the verified owner's profile lookup and holds the same slot through awaited Storage acknowledgement. GET enters before private Storage download and releases after its validated original-byte response is constructed. DELETE remains outside the slot. A scoped validator can be used once; a validation started by a callback is drained before capacity is released even if that callback returns early.

Deterministic tests use streams with `highWaterMark: 0` and explicit stage barriers. A second eligible request receives the existing typed `decoder_unavailable` 503 or private route 503 with `Retry-After: 60`; denied uploads have zero pulls and one non-awaited cancellation. Separate barriers cover raw read, PNG inspection, codec entry, upload acknowledgement and GET download. PUT and GET contenders share the raw validator's slot. Tests also check cheap denial precedence, Auth and own-profile outcomes while busy, verified upload cookies, DELETE independence, callback failure precedence, capacity recovery after invalid/missing/unavailable provider results, and an unread GET response that remains valid after later work succeeds. A callback-completion barrier proves that early callback return cannot release capacity while its started decode remains held. Recovery tests require an immediate valid photo after an active-reader abort, raw read timeout, missing WASM and a timed-out Storage upload. Separate pre-admission abort coverage preserves its cheap 400 denial. Existing photo tests also cover real pinned codec fixtures and Storage adapter behavior.

Initial implementation verification: `pnpm test` passed 223 tests in 25 files. `pnpm run typecheck`, `pnpm run lint` and `git diff --check` passed. An allowlisted synthetic Worker build, with a temporary HOME and no project dotenv files or private variables, completed and emitted `.open-next/worker.js`. The build compiled both dynamic photo routes; it did not execute a concurrent Worker request probe. After the tests-only recovery review fix, the three focused photo suites passed 43 tests; typecheck, lint and diff check passed again. No Worker rebuild was needed for that tests-only change.

This is source-level concurrency hardening, not total-memory or hosted acceptance. The slot does not control returned response or caller-retained bytes, prefetched request data, residual canceled host/native work, GC, other application buffers, or other isolates and replicas. Actual bundle module identity and second-request rejection before preflight still need a bounded Worker overlap check. Boundary corpus allocation/CPU characterization, target Workers plan and representative hosted route CPU/outcome measurements, memory acceptance, gateway/JWT/RLS/browser/cache checks and account-deletion cleanup remain open. Keep `ANTE_PROFILE_PHOTOS_MODE` unset until the release gate is resolved.

Task and [whole-plan independent reviews](2026-09-26-photo-processing-scope-review.md) accepted the source slice through `3c225bb` with no remaining findings. This is not runtime or hosted activation acceptance.

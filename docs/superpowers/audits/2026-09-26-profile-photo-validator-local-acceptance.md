# Profile photo validator: local Worker acceptance and release gates

Date: 26 September 2026. Scope: `Ante-Website` at `codex/shared-web-account`, starting from `698dff4`. This prepares a server-only validator. It does not create a permanent upload/serving route, authenticate a caller, authorize Storage ownership, or deploy anything.

## Build and dependency evidence

- Exact production dependencies: `@jsquash/png@3.1.1` and `@jsquash/jpeg@1.6.0` in `package.json` and `pnpm-lock.yaml`. Only their decode entries are imported. Installed decoder WASM files are 181,088 and 166,470 bytes (347,558 combined); these are source package sizes, not the full Worker bundle size.
- The first temporary Next route imported both `.wasm` files directly. `pnpm run build:worker` failed in Next 16.3.3 Turbopack: generated WASM loaders could not resolve PNG `wbg` or JPEG `a` imports, and neither file had a default `WebAssembly.Module` export. The second attempt configured Turbopack `*.wasm` as `bytes`; Next/OpenNext built, but the actual Wrangler 4.139.0 Worker returned `CompileError: WebAssembly.compile(): Wasm code generation disallowed by embedder`. Both temporary changes were removed.
- OpenNext [documents a custom Worker entrypoint](https://opennext.js.org/cloudflare/howtos/custom-worker) that delegates to its generated handler. `worker-entry.mjs` uses that same-Worker pattern. Wrangler statically imports each WASM file as a compiled module, passes it to the generated OpenNext fetch handler through `env`, and `getCloudflareContext().env` supplies it to the server-only validator. No runtime WASM fetch or code generation is used. The third temporary route returned 200 and decoded a synthetic 2×2 PNG and JPEG through the actual Worker. The final `wrangler.jsonc` keeps `workers_dev:false` and `preview_urls:false`.
- The local acceptance script `node scripts/check-profile-photo-worker.mjs` creates a route only when its path is absent, builds, runs Wrangler on `127.0.0.1`, exercises the validator, removes the route, and rebuilds without it. It uses only synthetic public configuration and fixtures. Final source, final `.open-next` output and browser assets contained no diagnostic route; browser assets contained no jSquash/mozjpeg codec code. No provider calls, real credentials, user photos or deployment were involved.
- After review, the diagnostic runner now constructs a narrow child-process environment (`PATH`, temporary `HOME`/`TMPDIR`, `CI`, telemetry disabled and three synthetic public values). It refuses root `.env*` or `.dev.vars*` files before creating a route because Next and Wrangler may load those independently of the child environment. No such files existed during the follow-up run. It does not move or read real local env files.

## Accepted input profile

- Only `image/png` and `image/jpeg` with a matching signature. The stream is capped at **2,097,152 bytes**, including unknown-length/chunked bodies, with a **10,000 ms** overall body-read deadline. Declared lengths above the cap are rejected early; actual bytes always govern. Missing/empty, malformed declared lengths and declared/actual mismatch are invalid input. On denial the reader is cancelled without awaiting an untrusted cancellation promise. Received chunks are copied before a producer can reuse their buffers.
- Width and height must each be 1–2048 and their product at most 4,000,000 before expansive decode. The validated original bytes are returned unchanged; metadata is **not stripped**. Fixed typed errors expose only `code` and HTTP status: invalid input 400, unsupported format 415, too large 413, invalid image 422, timed-out body 408, decoder unavailable 503.
- PNG: complete signature, one first 13-byte IHDR, legal PNG depth/color pair, compression/filter zero, bounded chunk traversal, CRC for every chunk, palette/transparency placement, contiguous IDAT, one empty final IEND, no trailing data. IDAT zlib output must equal the expected noninterlaced scanline count before package decode. Ordinary bounded uncompressed ancillary chunks such as `pHYs`, `gAMA`, `sRGB`, `tEXt`, `eXIf` and other explicitly listed uncompressed types are accepted. Unknown chunks, animated PNG, Adam7 interlace, `iCCP`/`zTXt` and compressed `iTXt` are outside this initial profile; compressed metadata is excluded to avoid an independent inflation path. The wrapper's CRC check is necessary because the pinned PNG Rust decoder [intentionally ignores checksums](https://github.com/jamsinclair/jSquash/blob/main/packages/png/codec/src/lib.rs).
- JPEG: bounded marker and entropy-scan traversal, baseline SOF0 or progressive SOF2, one 8-bit frame with 1/3/4 components, at least one scan and final EOI at the exact end. Conflicting or multiple frames, malformed segment lengths, truncation, appended payload or second image, unsupported frames and DNL are rejected. JPEG APP metadata remains in original bytes.
- Both exact pinned codecs fully decode accepted structures. The result must match the preflight width, height and `width*height*4` RGBA length. Decoder exceptions never enter public errors. Decode concurrency is limited to one active call per isolate, with no waiting queue of uploaded buffers; an overlapping call may receive fixed 503.
- The pinned JPEG decoder can return pixels for a scan cut down to one entropy byte while writing `Corrupt JPEG data: premature end of data segment`. Its supported instance-local `print`/`printErr` callbacks now retain only a boolean warning flag, suppress the raw text and turn any warning-bearing decode into fixed 422. The codec helper itself is `server-only`. Early unsupported MIME, invalid or oversize declared length, and already-aborted requests cancel an unlocked attached body without waiting. A zero-length IDAT chunk is accepted within a contiguous, otherwise complete IDAT sequence; an all-empty stream still fails decompression.

## Closed release gates

The pinned JPEG Emscripten glue has `getHeapMax()=>2147483648` and grows WASM memory; it has no exposed hard per-decode allocation cap. The pinned PNG decoder's [default internal allocation limit is best effort and excludes caller output](https://github.com/image-rs/image-png/blob/v0.17.10/src/decoder/mod.rs). Preflight dimensions, one active decode and local tiny-image success do not establish safety within Cloudflare's [128 MB per-isolate limit](https://developers.cloudflare.com/workers/platform/limits/), which is shared across concurrent requests. Target-plan CPU time, peak per-isolate memory and sustained malformed/concurrent behavior must be measured and accepted before any route invokes this validator. The current plan and hosted CDN, admission, ownership, Storage and browser acceptance gates remain open. Production photo upload/serving stays disabled.

Controller rulings retained from the temporary workflow ledger:

- Use pinned jSquash candidates for local-only validation/runtime work, with serving closed. This fits the existing backend authorization. If the candidate proves unsuitable, the cost is reversible dependency/source work; no user photos or live resources are affected.

The fix uses a narrow child environment and refuses local dotenv files. If this is stricter than needed, the cost is reversible runner complexity or requiring a clean local environment.

Final-review exclusions remain explicit: resource acceptance must cover the whole pipeline, including PNG inflation before the final-codec concurrency gate, and concurrent requests; hosted credentials/Auth/cache/transforms/cookies remain unverified; endpoint token correlation, quotas and deletion semantics require their own implementation tests. Mobile/legacy avatar migration, metadata stripping and financial work remain outside this slice. Existing Node/OpenNext warnings are documented and nonblocking.

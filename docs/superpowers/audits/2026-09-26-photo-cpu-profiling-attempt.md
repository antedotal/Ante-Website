# Local maximum-area photo CPU profiling receipt

26 September 2026. A final context-aware local run obtained a CPU profile of five sequential maximum-area PNG validations in the actual OpenNext Worker. Earlier attempts at commit `966f8a8` stopped before photo POSTs; the successful run used commit `2273029`, whose only delta from `966f8a8` was documentation. These measurements characterize one local machine and do not establish hosted CPU or isolate-memory acceptance.

## Method and versions

The existing [resource acceptance design](/Users/daniel/.codex/worktrees/ante-web-first-foundation/Ante-Website/docs/superpowers/audits/2026-09-26-private-photo-resource-acceptance-design.md) and [Cloudflare CPU profiling guidance](https://developers.cloudflare.com/workers/observability/dev-tools/cpu-usage/) informed the method. The temporary nonce-bearing route called the actual `validateProfilePhoto` in the built local OpenNext Worker. Wrangler was `4.139.0`, workerd `1.20260923.1`, OpenNext `1.20.6`, Next `16.3.3`, Node `26.8.2`; machine was macOS arm64, Apple M5 Pro. Lockfile SHA-256: `c6062235e2ecbc4668bc6cee48d30d70990a0dddb40e67c46d18e7e138f779bd`.

The deterministic synthetic PNG was RGBA16, 2000 × 2000 pixels, 43,271 compressed bytes, SHA-256 `73d3c99b6e77e0b273fa74f12ca362374a7d974b928da0aa56adef82fd929fc5`. Its sparse, highly compressible contents cover maximum decoded area and 16-bit PNG preflight, not worst-case compressed-input pressure. Full metadata is in [`run.json`](evidence/2026-09-26-photo-cpu/run.json). The build and preview used a narrow synthetic environment, isolated HOME, disabled telemetry, loopback HTTP/inspector, and `--local`; Wrangler reported only local self-reference and assets bindings. No provider or deployment operation occurred.

## Inspector diagnosis and bounded attempts

1. The [initial attempt log](/tmp/ante-photo-cpu-profile-20260926.log) shows a successful diagnostic OpenNext build, `wrangler dev --local --ip 127.0.0.1 --port 18787 --inspector-port 19229 --inspector-ip 127.0.0.1`, and a 200 readiness GET from the run's nonce route. Inspector `/json/list` advertised one `Cloudflare Worker` target at `/ws`. Node 26's native `WebSocket` emitted an empty error before `open`, so no CDP command or photo POST occurred.
2. Source inspection of installed Miniflare found that its inspector proxy requires an allowed `Origin` if `User-Agent` is present. A no-build loopback header capture proved Node's native client sends `User-Agent: node` with no `Origin`. A separate local reproduction of Miniflare's installed `ws` accept-then-close pattern produced `open` followed by `close`, so missing `Origin` is a concrete incompatibility but does **not alone explain** the initial pre-open error. Do not attribute the exact initial handshake failure to one header without its HTTP status.
3. A single [no-build comparison](/tmp/ante-photo-inspector-diagnosis-20260926.json) launched the existing clean Worker artifact. Native WebSocket again emitted empty error then close 1006. Installed `ws@8.21.0` with explicit `Origin: http://127.0.0.1` opened the same advertised `/ws` target and exchanged a CDP `Runtime.evaluate` response. The response was `Cannot find default execution context`, consistent with no application request having run yet in that diagnostic. This proves the inspector/CDP connection is available through that client. The comparison changed both client implementation and Origin, so it does not isolate which one resolved the native failure.
4. The [second temporary-route attempt log](/tmp/ante-photo-cpu-profile-final-20260926.log) shows the diagnostic Worker built and answered the nonce GET 200. The installed `ws` client connected, but `Runtime.evaluate(globalThis.__antePhotoCpuNonce)` did not return the nonce. The driver refused to start `Profiler` without confirming the actual app isolate. It did not record each CDP error/value, so the exact evaluation response in this attempt is unknown. No photo POST was sent.

## Successful context-aware run

The [context-aware driver](/tmp/ante-photo-cpu-context-profile-20260926.mjs) enabled `Runtime` before the nonce GET, retained exact execution-context events and CDP replies, then evaluated the nonce with an explicit `contextId`. The [CDP diagnostic](evidence/2026-09-26-photo-cpu/cdp-diagnostic.json) records `Runtime.executionContextCreated` for `Worker` context `193096353`; evaluating in that context returned the exact run nonce. This identified the app isolate before profiling. The raw profile establishes that profiling produced data; the retained enable/start fields labelled reply are command-shaped records, not exact success acknowledgements. The run produced a 64-node, 221-sample [raw CPU profile](evidence/2026-09-26-photo-cpu/photo-validation.cpuprofile).

The five sequential [request outcomes](evidence/2026-09-26-photo-cpu/outcomes.json) were all 200 with the expected nonce, dimensions `2000 × 2000` and 43,271-byte length. Worker `performance.now()` wall observations were 86, 67, 70, 64 and 64 ms; client wall observations were 93.9, 72.3, 74.8, 69.6 and 67.5 ms. The first profiled POST followed a readiness GET, so these are not independently fresh-isolate cold measurements.

The [profile summary](evidence/2026-09-26-photo-cpu/summary.json) covers a 511.114 ms sampling window: 324.295 ms sampled active, 33.638 ms sampled garbage collection and 149.325 ms sampled idle. The categories total 507.258 ms; the remaining 3.856 ms of the profile window is not represented by sample deltas. These categories come from `timeDeltas` on the entire profile window, including request and runtime activity; they are not measured CPU for each request, and should not be divided by five as a per-request CPU figure. Leaf samples aggregated by function name (not unique source frame) included `wasm-function[6]` 55.336 ms, minified `g2` 52.524 ms, `wasm-function[8]` 45.259 ms, an unnamed frame 41.996 ms and `read` 28.679 ms. WASM frames map to one anonymous `wasm://` module; minification prevents precise source-level attribution from this profile alone. The workload was a sparse, highly compressible PNG and does not cover near-cap entropy, JPEG, concurrent requests or full authenticated GET/POST routes.

# Mediated profile photo website implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the website's server-mediated current-photo reader, including bounded admission, exact-byte manifest verification and fresh final caller authorization, while keeping serving and writes operationally disabled.

**Architecture:** The caller JWT selects one immutable current asset; only then may server credentials obtain its frozen manifest and exact bytes. The existing full JPEG/PNG validator runs before a second fresh exact-token Auth check and caller resolver statement; the route constructs an uncached response only after both succeed. A route-entry deadline spans admission, initial session work, reads and final checks; the existing processing slot remains owned until decode and response construction settle.

**Tech Stack:** Next.js 16/OpenNext Cloudflare, TypeScript, installed Supabase SSR/JS SDKs, pinned jsquash JPEG/PNG codecs, Vitest.

**Spec:** `../Ante/docs/superpowers/audits/2026-09-27-server-mediated-profile-read-design.md` (approved source architecture); exact database interface: `../Ante/docs/superpowers/plans/2026-09-27-profile-photo-mediated-database.md`.

## Global Constraints

- Inspected website `codex/shared-web-account` at `1f74445`; accepted Auth prerequisite `d5a8018` already supplies 64 KiB successful Auth bodies, 10-second raw fetch-plus-body deadlines, sanitized errors and a 30-second initial SDK/session bound. Reuse it; do not replace it with another prerequisite-only slice.
- This plan completes all remaining website read source. No SQL implementation, hosted runner, provider call, credential inspection, deployment or gate activation belongs to these tasks. The paired backend package is separately implemented/reviewed.
- Only server-only `ANTE_PROFILE_PHOTOS_MODE=mediated-read-v1` can permit reads. Unset, `private-v1`, `generation-read-v1` and unknown values deny. Writes remain closed, including in the new mode. No UI, mobile, proof, payment, cleanup or normalization work.
- Canonical lowercase UUID owner; no query, arbitrary asset/key/URL, historical-generation endpoint, service fallback, signed URL, redirect, retry or latest-generation restart. Legacy resolves to private 404.
- Quotas remain the existing trusted Cloudflare visitor limit followed by exact verified-user read limit (60/min each). Consume each once. Existing callback/email and upload/delete quota namespaces/counts remain unchanged.
- Admission fetch-plus-body: 5 seconds, 16 KiB. Resolver/manifest/Storage fetch-plus-body: 10 seconds, JSON/error 16 KiB, photo 1–2,097,152 bytes. One 30-second wall deadline begins at GET route entry, including async params and both admissions; it never resets between phases.
- Successful normalized manifest: JPEG/PNG, positive integer dimensions fitting 1920×1080 or 1080×1920, integer byte_count, positive canonical decimal-string revision within PostgreSQL bigint, lowercase 64-hex SHA-256, transform regex `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`. Preserve exact normalized bytes, without re-encoding.
- Every photo outcome, including 405s and admission failures, has `Cache-Control: private, no-store`, `CDN-Cache-Control: no-store`, `Cloudflare-CDN-Cache-Control: no-store`, `Pragma: no-cache`, `Expires: 0`, and `Vary: Cookie`. No ETag, Last-Modified, Accept-Ranges or provider cache metadata; keep force-dynamic routes.
- Initial failed Auth returns no provisional cookies. All outcomes after successful initial verification preserve exactly its safe SSR refresh cookies, including final Auth denial. Service requests never receive cookies, caller bearer or client headers.
- A deadline cannot preempt synchronous WASM work. Keep the slot until decode settles, discard late output and start no later work. The slot does not bound retained response bytes or other isolates. Source tests do not establish hosted CPU/memory/cache or real-session compatibility.

## Review Focus

- A provider ignores abort or never resolves body cancellation: response work must terminate without starting another phase (Tasks 1–3).
- Aggregate phases each finish within their own limits but exceed 30 seconds: the route must still fail closed (Task 3).
- Revocation, clear/replacement or caller/target profile removal during download/decode: final authorization must discard buffered bytes (Task 3).
- Initial refresh succeeds but final Auth changes identity or fails: preserve only initial safe cookies and never serve bytes (Tasks 2–3).
- Exact repeated URLs, browser validators, and unsupported methods: every response remains uncached and never partial/304 (Task 3; actual CDN behavior remains a hosted gate).

### Task 2: Add selected-asset integrity reads and exact-token re-verification

**Files:**
- Modify `lib/server/profile-photo-store.ts`, `lib/server/profile-photo-session.ts`.
- Extend `tests/profile-photo-store.test.ts`, `tests/profile-photo-session.test.ts`; retain `tests/profile-photo-auth-fetch.test.ts` as prerequisite regression coverage.
- Update `.guidelines/design.md` with this task's selected-asset integrity and final Auth interfaces.

**Interfaces:**
- `CurrentPhotoSelection` is a readonly, internally branded `{ ownerId: string; assetId: string }`, constructed/frozen only after strict caller resolution. The brand is a misuse guard, not authorization. No route accepts this value from a client.
- `resolveCurrentProfilePhoto(ownerId: string, callerToken: string, signal?: AbortSignal): Promise<{kind:'current'; selection: CurrentPhotoSelection}|{kind:'not_found'}|{kind:'unavailable'}>` uses public apikey plus exact caller bearer at `resolve_profile_photo_v1`, body `{p_owner:ownerId}`. Require 200 application/json and accept only exact resolver shapes. Strict legacy/not_found means not_found; malformed/uncertain means unavailable. Do not load the photo-read service credential on these denials (admission has an independent service use).
- `ProfilePhotoReadManifest` mirrors the exact RPC current shape: `{kind:'current';asset_id:string;revision:string;sha256:string;mime:'image/jpeg'|'image/png';width:number;height:number;byte_count:number;transform_version:string}`.
- `readSelectedProfilePhoto(selection: CurrentPhotoSelection, signal?: AbortSignal): Promise<{kind:'found';manifest:ProfilePhotoReadManifest;bytes:Uint8Array;contentType:'image/jpeg'|'image/png'}|{kind:'not_found'}|{kind:'unavailable'}>` first calls service-only `profile_photo_read_manifest_v1` with `{p_owner:selection.ownerId,p_asset_id:selection.assetId}`. Require 200 application/json. Exact `{kind:'not_found'}` maps to not_found; otherwise require every exact current field, no extras, matching asset and all global bounds. Parse revision with BigInt, never Number; maximum `9223372036854775807`.
- Only a valid manifest permits one service `GET /storage/v1/object/profile-photos/<owner>/<asset>` at configured HTTPS origin. Use `serviceCredential()` opaque apikey-only / legacy service JWT apikey-plus-bearer forms unchanged. Require 200, nonempty body, exact manifest MIME/length and SHA-256 using `crypto.subtle.digest('SHA-256', ...)`. Only HTTP 400 JSON with `statusCode:'404'` and `code:'NoSuchKey'|'NoSuchBucket'` maps to not_found; service authorization failures, corrupt metadata/bytes and other uncertainty are unavailable. No provider URL/key comes from the manifest.
- `confirmCurrentProfilePhoto(selection: CurrentPhotoSelection, callerToken: string, signal?: AbortSignal): Promise<{kind:'current'}|{kind:'not_found'}|{kind:'unavailable'}>` makes one fresh caller resolver call and compares the identical asset. Legacy/not_found/different asset means not_found; malformed/error means unavailable. No service calls or restarts.
- `reverifyProfilePhotoSession(session: VerifiedPhotoSession, signal: AbortSignal): Promise<{kind:'verified'}|{kind:'failed';status:401|503}>` uses a new server-only Supabase JS client with public config, `autoRefreshToken:false`, `persistSession:false`, `detectSessionInUrl:false`, no cookies/storage/session injection, and `createAuthFetch(url, createProfilePhotoAuthFetch(url, localSignal))`. Invoke only `auth.getUser(session.token)`; compare canonical returned user ID with initial `session.ownerId`. Race the whole final SDK call against parent abort and a 10-second local cap, including initialization; clean up. Authentication denial or changed valid identity gives 401; malformed identity, 429, redirects, network/provider uncertainty or expiry of a bound gives 503. Return no cookies and do not mutate the initial provisional response. Initial verification/status behavior stays unchanged.
- Temporarily retain the existing `downloadProfilePhoto` export for the old route until Task 3 switches all callers and removes it. Task 2 is library preparation, not a releasable mode; do not enable any old mode between tasks. Reuse the same strict caller resolver parser rather than duplicating transport.

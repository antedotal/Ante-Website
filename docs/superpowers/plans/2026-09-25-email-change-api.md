## Task 1: Isolated SSR cookie stages and user admission

Add a small server-only isolated account SSR adapter alongside the current adapter, preserving existing callback/proxy semantics. Construct from a copied request cookie list, never mutate NextRequest/global cookies. Each stage owns its jar and pending cookie writes (including removals/options), uses accountConfig public credentials and accountCookieOptions, and can fork a deep independent stage from its current jar. Applying verified stages to a NextResponse must merge by cookie name in stage order so a later replacement/deletion wins and obsolete chunks are removed; enforce the shared Secure/Lax/path policy and private cache headers. No unverified write reaches an HTTP response implicitly. Expose enough typed operations for Task2 to get client, fork and explicitly apply stages; avoid generic mutable globals.

Extract normalizedEmail from email-auth.ts into a shared server-only validation helper without changing its existing acceptance rules. Add admitEmailChangeUser(userId,action) using existing fixed-five consumeCallbackLimit transport with HMAC namespaces website-email-change-request:v1: and website-email-change-confirm:v1:. Validate nonempty verified user ID, action fixed union, secret minimum32bytes; no caller quota/clock/function, no raw user IDs sent to store. Denied429Retry1..60, unavailable503Retry60. This is per-user admission after verified identity; visitor60 remains before Auth in Task2. Preserve existing namespaces and limits.

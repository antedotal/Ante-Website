# Mediated private profile photo reader contract

`GET /api/profiles/<ownerId>/photo` serves only the current immutable asset when the server-only `ANTE_PROFILE_PHOTOS_MODE=mediated-read-v1` gate is set. The gate is unset in deployment configuration. Unset, `private-v1`, `generation-read-v1` and unknown values deny reads. `PUT` and `DELETE /api/account/profile/photo` remain closed with private 503 after cheap request validation; rejected upload bodies are cancelled without waiting for their producers. The fixed-key upload, delete and owner-profile store helpers are dormant and are not called by these routes.

The GET route accepts a canonical lowercase owner UUID and no query. One 30-second wall deadline starts at handler entry before asynchronous route parameters resolve. Abort or deadline after entry returns 503, even if a provider or parameter promise later settles; a request already aborted at entry returns 400. The route admits the trusted Cloudflare visitor, verifies the caller with fresh Auth, then admits that verified user in the 60/min read namespace. Each admission is consumed once. A fail-fast per-module photo-processing slot then covers the complete read, decode, final authorization and response construction. Contention returns 503. The slot is per loaded module/isolate; it cannot preempt synchronous WASM work or bound retained response bytes.

Inside the slot, the route calls `resolve_profile_photo_v1` using the exact checked caller bearer and public apikey. Only an exact `{ "kind": "current", "asset_id": "<canonical UUID>" }` selects an asset. `not_found` and `legacy` mean 404; malformed or uncertain replies mean 503. There is no legacy or fixed-key fallback. The selected owner and asset are frozen in an internal selection. A service-only call to `profile_photo_read_manifest_v1` returns the exact current manifest for that selection. The service credential then reads only `profile-photos/<owner>/<asset>` from Storage; it never receives the caller bearer, cookies, Range or conditional headers. The adapter checks the strict manifest shape, immutable-object MIME and byte count, and SHA-256 over the complete original bytes. Exact missing-object receipts mean 404; any other failure or mismatch means 503. Resolver, manifest and Storage requests each have a ten-second fetch-plus-body bound, with 16 KiB JSON/error and 2 MiB photo bounds. They use no redirects, retries, signed URLs or alternate keys.

The route fully decodes the hash-verified JPEG/PNG using the production codec and requires the decoded MIME and dimensions to match the manifest. It then rechecks the original caller token with a separate, nonrefreshing fresh Auth request and calls the resolver once more with that same token. Only the identical asset is confirmed. A revoked or changed caller identity returns 401; clear, replacement, profile deletion or lost accepted friendship observed by the final resolver returns 404. Provider uncertainty returns 503. No later byte fetch, quota, restart or fallback occurs. If authority changes after the final resolver snapshot, already in-flight bytes cannot be retracted. The response is the original hash-verified byte sequence with `X-Content-Type-Options: nosniff`.

Every response from both photo routes, including success, admission errors, cheap write denials and explicit 405s, carries `Cache-Control: private, no-store`, `CDN-Cache-Control: no-store`, `Cloudflare-CDN-Cache-Control: no-store`, `Pragma: no-cache`, `Expires: 0` and `Vary: Cookie`. Provider validators, range and cache metadata are stripped. `Allow`, `Retry-After` and safe initial SSR refresh cookies are retained. Initial failed Auth discards provisional cookies; every outcome after successful initial verification retains them. Range and conditional requests still run the full pipeline and return either a complete 200 image or a fixed private denial. Both routes are force-dynamic.

The current service-only manifest protocol supersedes the earlier rule that a caller bearer reads Storage directly. Ordinary direct Storage denial remains a backend requirement. Earlier [Storage](../superpowers/audits/2026-09-26-private-photo-storage-protocol.md) and [route](../superpowers/audits/2026-09-26-private-photo-route-local-acceptance.md) receipts document the retired implementation, not this serving contract. The [hosted reader operator record](../superpowers/audits/2026-09-27-profile-reader-hosted-operator.md) covers the backend authority separately. This website source and local tests do not activate serving or prove hosted Worker, cache, real-session, decoder resource or SQL behavior. Activation and rollback require separate reviewed hosted gates; rollback closes this mode without restoring user-Storage reads. Compression/upload normalization and retention remain separate work.

Fixed resolver/manifest JSONB RPC replies may carry exact HTTP 200 `Content-Range: 0-0/*` singleton metadata, with absent `Range-Unit` or literal `items`; their exact union/manifest validators remain mandatory. This exception never applies to Storage bytes, which still reject every provider range/partial 206 and require complete MIME, byte-count, hash and codec attestation. Manual handling rejects every redirect. Serving/publication modes remain closed pending hosted acceptance.

# Website account visitor admission

Protected `/account` pages and valid `GET`/`PUT /api/account/ante-presets` requests consume one account visitor admission before SSR client construction or Auth verification. The static `/account/sign-in` entrypoint skips server Auth and admission. The page proxy matches `/account/:path*`; API routes admit themselves, so an API request is not charged twice. Canonical URL, Host, supplied Origin and forwarded headers are checked before account admission. Preset query and write-body validation also precede admission. Unsupported preset methods return private bodyless 405 with `Allow: GET, PUT` before admission.

The server calls only `public.consume_website_account_limit(p_visitor_hash text)` through the configured Supabase project's REST endpoint. It sends an HMAC-SHA-256 lowercase hex digest of `website-account:v1:` plus the canonical single `CF-Connecting-IP`. IPv4-mapped IPv6 shares the IPv4 bucket; malformed, multiple, cross-zone sentinel and `CF-Worker` identities fail closed. `X-Forwarded-For`, `X-Real-IP` and `CF-Connecting-IPv6` cannot select the visitor. `ANTE_AUTH_INGRESS=cloudflare` must be explicitly enabled only for direct Cloudflare ingress, and `ANTE_AUTH_LIMIT_HMAC_SECRET` must contain at least 32 UTF-8 bytes.

This account RPC permits at most 60 admissions per visitor in the SQL rolling 60-second window. It is distinct from the five-per-minute callback/email RPC and HMAC namespaces. The service-only `SUPABASE_SECRET_KEY`, or a legacy `service_role` JWT, is used only in this fixed admission call. Incoming Authorization and cookies are never forwarded. All Auth and account-data RPCs use a request-scoped public-key SSR client, with owner authority derived from the verified user and `auth.uid()`.

An admission reply is exactly `{ "allowed": true, "retry_after_seconds": 0 }` or `{ "allowed": false, "retry_after_seconds": N }` with integer `N` from 1 through 60. A valid denial returns private 429 with matching `Retry-After`; missing configuration, missing trusted visitor identity, transport failure or malformed reply returns private 503 with `Retry-After: 60`. The adapter times out after five seconds, does not cache or follow redirects, and does not read failed provider response bodies. Logs use fixed labels with no visitor, digest, secret or provider details. Responses before verified identity carry no provisional session cookies.

The paired Ante SQL project owns the rolling-window implementation and service-role grants. Website mock tests cover request ordering and the REST adapter; a synthetic local Worker smoke covers denial behavior. Those checks do not establish hosted ingress, actual REST authorization, provider sessions or deployment.

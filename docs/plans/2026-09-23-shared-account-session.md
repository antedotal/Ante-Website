# Shared Ante website account session

**Status:** Executable, website-only prerequisite to the conditional web-first financial plan. No card, subscription, or live-money behavior is activated.

**Specs:** `../../../Ante/docs/superpowers/audits/2026-09-21-web-first-financial-commitment-design.md` and `../../../Ante/docs/superpowers/audits/2026-09-21-subscriptions-and-spec-review.md` in the ordinary sibling checkout. The account/session portion of Task 2 in `../../../Ante/docs/superpowers/plans/2026-09-21-web-first-financial-commitments.md` is the source; its funding sections remain deferred.

**Review Focus:** A forged or expired cookie must not render `/account`; a refresh must preserve the new cookies and non-cacheable headers; a callback cannot redirect off-site or leak tokens even with hostile Host headers; missing or placeholder Supabase configuration or canonical site origin must fail closed. Preserve an upstream Auth 429 with retry guidance. A durable per-visitor callback limit remains an Important deployment gate until the host and trusted IP source are known. The deployment gate separately compares the website and mobile project URLs. Marketing `/signup` remains the waitlist.

## Task 1: Add the shared website session boundary

1. Preserve the existing waitlist behavior and static routes. Add `@supabase/ssr` and a small Vitest runner using pnpm. Use the existing pinned lockfile and explicit targeted build-script policy; do not upgrade unrelated dependencies. Add `test` and `typecheck` scripts.
2. Write failing tests first for required account configuration, browser/server client separation, cookie refresh propagation, server-verified identity for `/account`, safe callback code exchange and same-origin redirect, malformed/expired callback handling, and no token exposure. Tests must assert behavior, not just source text or mocks of the code under test. Establish RED before production changes.
3. Implement account-only `lib/supabase/client.ts` and `server.ts` with required project URL and publishable/anon key from the same Ante project, plus a required canonical website origin. Use `createBrowserClient` only in the browser and `createServerClient` with Next cookies on the server. Keep service-role keys out of client code. Do not reuse the legacy marketing client as an account authorization boundary.
4. Implement Next 16 `proxy.ts` for account/auth routes so refresh cookies reach both Server Components and browser. Protect a minimal `/account` page on the server with verified claims or `getUser`; do not use `getSession().user` as authorization. Prevent caching of personalized responses.
5. Implement a separate `/account/sign-in` route for Google OAuth and `/auth/callback` for PKCE code exchange, with a configured canonical site origin, fixed post-login destination, hostile-host rejection, and safe error codes. Do not offer email/password while the mobile app disables it. Keep this new route unlinked from public marketing until shared-project provider/redirect configuration and actual native-first/web-first identity tests pass. Sign in with Apple on iOS and web is a separate confirmed follow-up; this slice must not claim that requirement is done.
6. Update `.guidelines/design.md` with the account route and limits. Run focused RED/GREEN, then `pnpm test`, `pnpm run typecheck`, `pnpm run lint`, `pnpm run build`, and `pnpm install --frozen-lockfile`. Record any external provider, deployment, or device tests not run. Commit only the website-owned slice on its isolated branch.

**Acceptance:** The source/test/build checks pass; unauthenticated, malformed, and hostile-host account access fails closed; website account auth requires explicit Supabase and canonical site-origin configuration without placeholder fallbacks; no billing or financial controls are exposed. Deployment configuration must target the same project as the mobile app. Actual same-UUID Google/Apple sign-in remains an explicit integration gate, not inferred from mocked tests.

# Task 1 implementation report

Status: source and local-runtime acceptance complete; production activation closed.

Implemented a server-only `validateProfilePhoto(Request)` returning original validated JPEG/PNG bytes, MIME and decoded dimensions, with fixed typed error codes/statuses. The 2 MiB/10 s stream limit, complete PNG/JPEG structural preflight, CRC and IDAT inflation checks, 2048-axis/4-million-pixel limits, full pinned jSquash decode, result consistency and one-at-a-time decoder gate are in focused modules under `lib/server/profile-photo-*`. Exact codec dependencies are pinned. `worker-entry.mjs` is the documented custom entrypoint for the same generated OpenNext Worker and supplies Wrangler's precompiled static WASM modules through the request context. No permanent route, provider call, deployment, paid service or user photo was introduced.

Loader proof: direct `.wasm` imports in the temporary Next route failed in Turbopack (`wbg`/`a` unresolved; no default module export). Turbopack `bytes` succeeded in building but actual workerd rejected `WebAssembly.compile()` as disallowed. The same-Worker custom entrypoint then decoded valid synthetic 2×2 PNG/JPEG via OpenNext/Wrangler without runtime fetch or compile. The temporary route was removed and the build regenerated without it.

TDD: the initial tests were RED because the validator module was absent; after implementation, 11 focused tests are GREEN. A later RED case exposed mutable stream-chunk reuse and was fixed by copying admitted chunks. Another RED case exposed missing Worker-context misclassification and was fixed to generic 503.

Final checks on final source: `pnpm test` **20 files / 170 tests passed**; `pnpm run typecheck` exit 0; `pnpm run lint` exit 0; `node scripts/check-profile-photo-worker.mjs` exit 0, including Next/OpenNext Worker builds with and then without the diagnostic route. Actual local Worker cases: valid PNG, baseline/progressive JPEG and 2048×2 fixtures 200; MIME mismatch, CRC/IDAT/inflation, overlong/trailing PNG, oversized dimensions, truncated/double JPEG 422; APNG/interlace 415; streamed 2 MiB+1 413; four concurrent tiny inputs and following same-isolate recovery 200. Final source/build/browser artifacts contain no temporary route; browser artifacts contain no codec code. Port 8787 has no remaining listener. The full acceptance record is `docs/superpowers/audits/2026-09-26-profile-photo-validator-local-acceptance.md`.

Observed local handler wall time on tiny/wide synthetic fixtures was 0–4 ms; first cold client request about 105 ms, subsequent client requests about 2–8 ms. The local check did not expose reliable Worker CPU or peak isolate memory. The pinned JPEG Emscripten heap can grow toward 2 GiB and the PNG internal limit is best effort and excludes output; input/dimension caps and one-at-a-time decode do not prove safety within Cloudflare's shared 128 MB isolate. This resource question, target-plan CPU, hosted CDN/admission/ownership/Storage/browser checks are release gates. Keep production photo serving disabled.

Warnings: Node `module.register()` deprecation and OpenNext experimental Node middleware messages during build; account-admission tests emitted their expected fixed denial labels. No failed final gates.
